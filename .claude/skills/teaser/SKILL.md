$ARGUMENTS 로 짧은 홍보 영상을 만든다. 이야기 · 화면 · 소리 · 렌더를 이 컴퓨터에 이미 있는 도구로 직접 만든다. 번들 에셋도 외부 생성 서비스도 쓰지 않는다.

```
영상 속 사실(이름 · 숫자 · 기능 · 후기)은 프로젝트에 있는 것만. 연출 문구는 지어내도 된다.
비밀 · 실제 사용자 정보는 영상 · 문구 · 중간 파일 어디에도 들어가지 않는다.
```

원본: [latent-spaces/brag](https://github.com/latent-spaces/brag)의 `brag-slim` · `brag` 스킬 (MIT, Copyright (c) 2026 Shunit Haviv Hakimi). base 규칙에 맞춰 다시 썼다.

## 입력

| 옵션 | 기본값 |
| ---- | ------ |
| 입력 | 비우면 현재 프로젝트. `http(s)://` 주소나 `example.com` 같은 도메인이면 웹사이트 |
| `--tone <프리셋 또는 자유 서술>` | 프로젝트를 보고 고른다. 애매하면 `default` |
| `--style <프리셋>` | 없음 — 프로젝트 색 · 글꼴로. 원하면 `promo/assets/styles/STYLES.md` 6개 중 하나 (`node style.mjs showcase` 로 견본 보고 `use <이름> --brand <브랜드 색>`) |
| `--format landscape\|vertical\|square` | landscape 1920x1080 (vertical 1080x1920, square 1080x1080), 30fps |
| `--duration <초>` | 약 20초 (15~25) |
| `--no-music` · `--no-sfx` | 음악 · 효과음 켬 |

플래그 대신 말로 해도 된다 ("세로로, 영화 예고편처럼"). 특정 기능 · 새 버전만 짚으면 그것을 영상의 중심으로 삼는다. 입력이 어느 쪽도 아니고 현재 폴더가 프로젝트도 아니면 무엇을 자랑할지 묻는다.

## 출력

`video-output/teaser-YYYYMMDD-HHmmss/`. 중간 파일(프레임 · 내려받은 이미지 · 스크립트 · 소리 조각)은 그 안의 `work/`에 둔다.

| 파일 | 내용 |
| ---- | ---- |
| `teaser.mp4` | 영상. 0번째 프레임이 포스터 |
| `teaser.jpg` | 포스터 (가장 좋은 정지 장면) |
| `plan.md` | 조사 답 · 기획 · 장면표 |
| `share-copy.txt` | 공유 문구 1~3문장 |

`video-output/`이 `.gitignore`에 없으면 추가한다. 영상 · 프레임을 커밋하지 않는다.

## 1. 조사

### 프로젝트

읽는 것: 메인 화면 · 라우터, 색 토큰(`index.css` 등)과 글꼴, README, 핵심 컴포넌트, 화면 문구 상수. 가장 좋은 재료는 **쓰는 모습**이다. 진입 → 핵심 동작 → 결과의 2~3박자를 찾는다.

소스가 있으니 직접 쓴다. 실제 컴포넌트 · 스타일 · 글꼴 · 이미지 · 애니메이션을 가져오거나 렌더해서 영상에 넣고, 다시 그리는 건 가져올 수 없는 것만.

실제 화면을 찍으려면 개발 서버가 켜져 있어야 한다. 켜져 있지 않으면 사용자에게 켜 달라고 하거나, 컴포넌트 · CSS 를 가져와 영상용 HTML 로 그린다. 로그인이 필요한 화면은 시험 계정 · 게스트로만 찍는다.

### 웹사이트

방문자가 보는 그대로 가져온다. 단순 다운로드가 빈 껍데기면 헤드리스 브라우저로 렌더한다. 쿠키 배너 · 팝업을 닫고, 스크롤해야 나타나는 내용이 있으니 구역별로 내리며 찍는다.

- 문구: 제목 · 태그라인 · 구역 제목 · 기능 이름 · 버튼 문구 · 후기, `<title>` · meta description · 공유 미리보기 태그
- 정체성: CSS 의 실제 색, 불러오는 글꼴
- 이미지: 로고 · 제품 화면 · 대표 이미지 · 데모 영상 (쓸 것만 `work/`에)
- 쓰는 흐름: 데모 영상 · "이렇게 써요" 구역 · 문서

### 읽지 않는 것 (입력과 무관)

- `.env` · `.env.*` (CLAUDE.md 원칙 7. base 계열은 `.env`를 git 에 추적하므로 "추적 중이니 읽어도 된다"가 아니다)
- 키 · 인증서(`.pem` · `.key` · `id_rsa` · 서비스 계정 JSON), `secrets/` · `credentials/` 폴더, 토큰이 든 로컬 설정
- `dist/` · `build/` · `node_modules/`, lock 파일, `.git/`, 테스트

### 비밀이 이 단계를 넘지 않는다

여기서 읽은 것은 공개 영상에 나올 수 있다. 비밀 · 키 · 토큰, 내부 호스트 · 주소, 운영 도메인 밖의 서버 주소, 실제 사용자 이름 · 닉네임 · 이메일 · 기록(랭킹 등)을 `plan.md` · 영상 · 문구 · `work/` 에 옮기지 않는다. 실제 화면에 그런 데이터가 있으면 그럴듯한 가짜 값으로 바꾸고 plan 에 적는다.

### 답할 것 (통과 조건: 전부 답함)

`plan.md` 맨 위에 적는다.

1. 이건 뭔가 (한 문장)
2. 누구를 위한 것이고 그 사람에게 무엇을 해 주나
3. 다른 것과 무엇이 다른가
4. 가장 인상적이거나 웃긴 한 줄 (프로젝트 안에 있는 문장)
5. 시각적 훅 (가장 강한 화면 · 색 · 요소)
6. 보여 줄 실제 화면 · 흐름 (진입 → 핵심 동작 → 결과). 없으면 "없음, 소개 페이지만"
7. 톤 (프리셋 + 이 프로젝트용 한 구절)
8. 공유 문구 초안 한 줄

## 2. 계획 (통과 조건: 장면 길이 합이 목표 ±1초, 읽기 시간 충족)

`plan.md`에 각도 · 훅 · 하이라이트 2~3개 · 마무리 · 톤 · 색 · 글꼴, 장면표(번호 · 길이 · 화면 · 문구 · 움직임 · 소리)를 쓴다.

기본 모양: 훅(2~3초) → 공개(2~4초) → 하이라이트 2~3개 → 마무리 · 로고(2~4초). 틀이 아니라 출발점이다.

### 만드는 규칙

- **짧게.** 15~25초, 18~22초가 가장 좋다.
- **처음 보는 사람이 알아듣게.** 한 번 보면 무엇인지, 누구 것인지, 어디서 쓰는지 안다. 어떻게 만들었는지(스택)는 뒤로.
- **훅이 전부다.** 첫 2초에 계속 볼지 정해진다. 훅부터 계획한다.
- **진짜를 보여 준다.** 실제 UI · 컴포넌트 · 문구 · 이미지를 재사용한다. 소개 페이지보다 일하는 앱. 쓰는 모습의 작은 UI 문구(파일 이름, "저장했어요" 토스트)는 지어내도 되지만, 지어낸 주장 · 숫자 · 후기는 안 된다. 의미 없는 추상 그래픽으로 채우지 않는다.
- **이 프로젝트만의 것.** 프로젝트 자신의 문구를 쓴다. "업무를 효율적으로", "혁신적인 경험" 같은 범용 문구 금지 (`rules/writing.md` 3절).
- **읽을 수 있게.** 속도는 움직임과 컷으로 내고, 글을 일찍 치우지 않는다. 읽어야 하는 줄은 다 나타난 뒤부터 한 어절에 약 0.3초, 짧은 라벨도 최소 0.8초 머문다. 배경 질감용 글자는 예외.- **살아 있게.** 하나씩 나타나기, 클릭 · 스와이프 · 타이핑 흉내가 정지 슬라이드보다 낫다.
- **웃음은 프로젝트 자체에서.** 억지로 웃기지 않는다.
- **어느 프레임을 멈춰도 올릴 만하게.**

### 문구

- 화면 · 공유 문구는 `rules/frontend/copy.md` 를 따른다 (client 해요체, 맞춤법 · 띄어쓰기, 이름 뒤 조사). 영어 프로젝트면 원문 언어.
- 이모지를 쓰지 않는다 (CLAUDE.md 원칙 13).

### 톤

톤(속도 · 장면 수)과 디자인 스타일 프리셋(색 · 글꼴 · 모양)은 따로 고른다. 예: 블록 팝 + chaotic, 코발트 보고서 + polished.

프리셋은 기본값이고, 자유 서술("2016년 가짜 시리즈 A 발표")이 있으면 그것을 살려 가장 가까운 프리셋의 속도만 빌린다.

| 톤 | 느낌 | 장면 · 전환 |
| -- | ---- | ----------- |
| `default` | 경쾌, 장난스러움, 깔끔 | 4~5장면, 부드러운 전환 |
| `polished` | 진지, 절제 | 3~4장면, 길게 머묾, 페이드 |
| `yc-parody` | 스타트업 발표를 정색하고 흉내 | 4~5장면, 장면당 주장 하나, 하드 컷 |
| `chaotic` | 빠르고 시끄럽게 | 6~8장면, 2초 미만 장면 섞음, 번쩍 · 줌 컷 |
| `deadpan` | 담담, 아무것도 농담 아닌 척 | 3~4장면, 넓은 여백, 느린 페이드 |
| `cinematic` | 예고편 규모 | 4~5장면, 큰 글자, 와이프 |
| `app-store` | 깔끔한 기능 카드 | 4~6장면, 미끄러지는 전환 |

### 소리

음악과 효과음을 한 곡처럼 만든다. 효과음은 음악과 같은 키 · 같은 공간감으로 섞고, 음악 밑에 부드럽게 둔다. 날카롭거나 튀는 소리, 반복되는 작은 소리는 뒤로 뺀다. 마지막은 페이드로 닫는다.

- 소리는 로컬에서 합성한다 (ffmpeg `aevalsrc` · `sine` 필터, 브라우저 `OfflineAudioContext` 등). 사용자가 라이선스를 아는 음원 파일을 주면 그것을 쓴다.
- 음성 내레이션은 하지 않는다. 필요하면 사용자가 따로 요청한다.
## 3. 만들기 · 확인 (통과 조건: 모든 장면과 전환 중간의 정지 화면을 직접 봤고 문제 0)

도구는 이 컴퓨터에 있는 것으로 고른다. 먼저 확인한다: `ffmpeg -version`, `node --version`, 프로젝트에 Playwright(`@playwright/test` · `playwright`)가 있는지. 없으면 **설치하지 않고** 사용자에게 무엇이 필요한지 말한다 (새 의존성은 승인 대상).

**처음부터 짜지 않는다.** `/promo` 스킬의 `assets/`(엔진 · 부품 · 스크립트 · 틀)를 같이 쓴다. 쓰는 법과 함정은 `promo/assets/PARTS.md`.

```bash
SK=<스킬 폴더>/promo/assets
mkdir -p <출력>/work && cd <출력>/work
cp $SK/*.mjs $SK/engine.js $SK/parts.css $SK/template/* .
cp -r $SK/styles .                # 디자인 스타일 프리셋을 쓸 때 (STYLES.md)
export PW_FROM=<프로젝트에서 @playwright/test 가 깔린 폴더>
```

- 실제 화면: 틀 `capture.mjs`를 채운다 (사이트 화면은 1280x720 `dsf 3`, 개발 서버 오류 창 확인 · 앱 안내 문구 숨기기는 `capture-lib.mjs`가 한다). 찍은 것은 한 장에 모아 바로 본다.
- 영상: 틀 `composition.html` · `timeline.js`를 장면표대로 채운다. 모든 프레임은 **시간 t 만의 순수 함수**(`renderAt(f)`), 전환은 `V.placeScenes`, 글자 등장은 `V.blurSlide`. 읽는 글은 `.read`(66px) · 보조는 `.read-sub`(44px).
- 확인 프레임: `node render.mjs v1 <프레임...>` — 장면마다 한 장, 전환 중간마다 한 장. 한 장에 모아 Read 로 본다. 넘침 · 겹침 · 잘림 · 낮은 대비 · 빈 화면을 고친다. 복잡한 두 화면의 단순 크로스페이드는 이중 노출처럼 탁해진다. 앞 내용을 빼고 새 내용을 넣거나, 배경색을 한 번 거친다.
- 전체 렌더: `node render.mjs` — 자동 검사(장면 밖으로 새는 요소 · 글자 크기 · 1배 아래 확대) 뒤 브라우저 4개 병렬.
- 소리: `sfx.js`를 채우고 `node synth.mjs`.

## 4. 렌더 · 전달

1. `node finish.mjs --name teaser --poster <프레임>` — 묶기(H.264 · `yuv420p` · AAC · `+faststart`), 포스터 `teaser.jpg`를 0번째 프레임에 굽기, `ffprobe`, 소리 싱크 측정, 컨택트 시트를 한 번에.
2. 포스터 프레임: 가장 강한 장면이 **다 자리 잡은** 순간(글자가 다 들어왔고 나가기 전). 대부분의 플랫폼(슬랙 · X · 디스코드)은 첫 프레임을 썸네일로 쓰고, 프레임을 추가하지 않고 바꾸므로 길이 · 소리 싱크가 그대로다.
3. 출력의 길이 · 해상도 · fps 가 계획과 맞는지, 싱크가 0샘플인지 확인하고, 컨택트 시트(`work/qa/contact-final.jpg`)로 전체 흐름을 본다.
4. `share-copy.txt`: 1~3문장, 그대로 올릴 수 있게, 이 프로젝트만의 내용, 톤에 맞게. "기쁜 마음으로 공유합니다" 같은 범용 문구 금지.

## 보고

- 영상 · 포스터 · 문구 경로, 길이 · 해상도 (`ffprobe` 결과로)
- 각도 한 문장
- 가짜 값으로 바꾼 데이터가 있으면 무엇을
- 묻지 않고 내린 결정 (톤 · 포스터 시점 · 생략한 장면)
- 다음 선택지: 장면 하나 다시, 다른 톤, 세로판

## 하지 않는 것

- 영상 · 문구를 어디에 올리기 · 게시하기 · 외부 호스팅 (사용자가 따로 요청해야 한다)
- 과금되는 외부 API (TTS · 음악 · 이미지 · 영상 생성). 필요하면 CLAUDE.md 원칙 12 대로 모델 · 횟수 · 예상 금액을 먼저 묻는다
- 프로젝트 의존성 추가, 전역 도구 설치
- 프로젝트 코드 수정. 화면을 바꾸고 싶으면 `/design`
- `video-output/` 커밋
