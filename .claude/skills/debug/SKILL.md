$ARGUMENTS 의 원인을 조사한다. **파일을 고치지 않는다.** 수정은 `/fix`.

```
원인을 코드에서 확정하기 전에는 수정을 제안하지 않는다.
```

## 입력

- 필수: 증상 (`$ARGUMENTS`)
- 있으면 좋은 것: 기대 / 실제 동작, 재현 절차, 오류 메시지 · 로그, 최근 변경, 환경

## 1. 증상 정리 · 재현 판단

- 증상, 기대 / 실제, 재현 절차, 환경을 정리한다. 모르는 항목은 "모름".
- 오류 메시지 · 로그는 **최초 실패 지점**을 찾고 파생 오류와 구분한다. 비밀 값은 `[redacted]`.
- **재현 가능성**: 절차대로 코드를 따라갈 수 있는가, 간헐적인가(타이밍 · 캐시 · 세션 · 동시 요청), 환경 의존인가. 재현 정보가 부족하면 어떤 정보가 필요한지 먼저 알린다.
- 최근 변경: `git log --oneline -10`, `git diff --stat`.

## 2. 조사

증상 위치에 따라 **be-researcher** · **fe-researcher**(애매하면 둘 다) 호출. 증상과 연결되는 코드 경로만 좁게 읽게 한다.

## 3. 원인 좁히기

| 후보 | 근거 | 확인 위치 (파일:줄) | 맞다면 보일 증거 | 아니라면 배제할 증거 |
| ---- | ---- | ------------------- | ---------------- | -------------------- |

- 후보는 **3개 이하**.
- **동작하는 비슷한 코드**를 찾아 차이를 전부 나열한다.
- 프론트 → API → 서비스 → DB처럼 경계가 여러 개면 **어느 경계에서 깨지는지** 먼저 확정한다. 각 경계의 입력 · 출력을 확인할 방법(네트워크 탭, 로그, `curl`)을 적는다.
- 가설은 한 번에 하나. 틀리면 덧붙이지 말고 새 가설.
- 후보를 배제할 때도 근거(파일:줄 · 출력)를 남긴다.

## 4. 결론

- **확정**: 원인 파일:줄, 왜 그 증상이 나는지 한두 문장, 수정 방향(고치지는 않음), 영향 범위(같은 원인이 다른 곳에도 있는지 Grep), 재발 방지 케이스(Given / When / Then).
- **미확정**: 확인한 것, 배제한 후보와 근거, 남은 후보, **다음에 확인할 가장 작은 방법**(사용자가 해 줄 것 포함).

"원인 없음"이라는 결론은 거의 항상 조사가 덜 된 것이다. 미확정이면 그렇게 적는다.

## 돌려줄 형식

```
## 원인: 확정 / 미확정

증상 · 재현: ...
최초 실패 지점: ...
최근 변경 중 관련: ...

### 후보 표
| 후보 | 근거 | 확인 위치 | 맞다면 | 아니라면 | 결과 |

### 결론
- 원인 (파일:줄):
- 수정 방향 (미실행):
- 같은 원인이 있을 수 있는 곳:
- 재발 방지 케이스:

### 다음 단계
- /fix 로 진행 / 추가 확인 필요 (무엇을)
```

## 하지 않는 것

- 파일 수정, 수정 명령 실행
- 근거 없는 후보를 원인으로 단정
- 마지막 로그 줄만 보고 판단
- 여러 가설을 동시에 밀기
