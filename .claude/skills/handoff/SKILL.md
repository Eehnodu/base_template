$ARGUMENTS 작업을 다음 세션이 바로 이어받을 수 있게 기록한다. **기억이 아니라 파일 상태를 근거로 쓴다.**

## 1. 현재 상태 확인

- `git status --short`, `git diff --stat`, `git log --oneline -5`, 현재 브랜치
- `.claude/last-verify.json`(마지막 검증 마커)과 `zz_docs/TODO.md` "마지막 검증"
- 대화에서 결정한 것 · 승인받은 것 · 보류한 것

## 2. 초안

`zz_docs/TODO.md`의 **"진행 중"** 섹션(없으면 "마지막 검증" 표 아래에 만든다)에 들어갈 내용:

```
## 진행 중 — [작업 이름] (YYYY-MM-DD HH:mm)

- 목표:
- 상태: 진행 중 / 막힘 / 리뷰 대기
- 완료: (체크박스)
- 진행 중 · 남은 일: (체크박스, 순서대로)
- 변경 파일: 경로 — 이유 (미커밋이면 표시)
- 검증 상태: 마지막 /verify 범위 · 결과 · 그 뒤 바뀐 파일 / 미실행
- 결정 (묻지 않고 내린 것 · 승인받은 것): 결정 — 이유
- 막힌 것 · 질문:
- 다음 세션 첫 명령: (예: "/verify all", "/fix ... 4단계부터")
```

민감 값 · 토큰 · 개인정보는 넣지 않는다. 모르는 것은 추정하지 말고 "확인 필요".

## 3. 반영

- 초안을 보여 주고 TODO.md에 반영한다. 기존 기록은 지우지 않고 갱신한다. 끝난 작업이면 "진행 중" 섹션을 지우고 "완료"로 옮긴다.
- "마지막 검증" 표가 현재 상태와 다르면 함께 고친다.
- 그날 CHANGELOG에 아직 안 적힌 작업이 있으면 한 줄 추가한다.

## 4. 보고

- 다음 세션이 처음 읽어야 할 것: `zz_docs/TODO.md` "진행 중" + `git status`.
- 미커밋 변경이 있으면 커밋할지 묻는다 (`/pr`).
- 컨텍스트가 길어서 정리한 것이면 `/compact` 초점 문장을 제안한다: "변경 파일 · 결정 · 검증 상태 · 다음 작업 중심으로".

## 하지 않는 것

- 코드 수정
- 기억으로 검증 결과를 쓰기 — 마커 · TODO · 실제 출력만
- 실패 · 미실행 · 막힌 것 숨기기
- 이전 기록 삭제
