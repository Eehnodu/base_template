$ARGUMENTS 문서를 코드 근거로 작성 · 검토한다. **문서의 역할은 예쁜 글이 아니라 시스템과 문서의 차이를 줄이는 것이다.**

## 입력

- 필수: 대상 (`$ARGUMENTS`)
- 있으면 좋은 것: 대상 독자(신규 개발자 · API 사용자 · 운영자), 목적, 유지해야 할 기존 내용

## 1. 대상 · 독자 확정

- 어떤 문서인가: `zz_docs/LOGIC.md`(모듈 · API · 에러 코드), `README`(설치 · 실행 · 검사), API 문서(엔드포인트 · 요청 · 응답 · 에러 · 인증), 온보딩(폴더 · 명령 · 첫 작업), 기타
- 독자와 목적이 없으면 질문한다. 독자에 따라 넣을 내용이 다르다.
- 기존 문서가 있으면 **유지해야 할 경고 · 제약**을 먼저 표시한다.

## 2. 근거 읽기

문서 유형별로 먼저 확인할 파일:

| 문서 | 먼저 읽을 것 |
| ---- | ------------ |
| LOGIC.md | `app/module/__init__.py`, 각 `*_router.py` · `*_service.py`, `fail(...)` 호출부, `scripts/check_routes.py api` 출력 |
| README · 온보딩 | `package.json` scripts, `requirements.txt`, `run.sh` · `migrate.sh`, `.env.example`, CLAUDE.md "자주 쓰는 명령" |
| API 문서 | 라우터 데코레이터(`@with_login`), service 반환 dict, 프론트 `types/` |

## 3. 초안 — doc-writer

**doc-writer** 호출 → 대상 · 독자 · 근거 파일 · 유지할 내용을 넘긴다. 초안에는 근거 파일 목록이 붙고, 확인하지 못한 문장은 "확인 필요"로 표시된다.

## 4. 검토

초안을 코드와 다시 대조한다.

- 코드와 맞지 않는 설명, 존재하지 않는 명령 · 경로
- 근거 없는 추정이 사실처럼 쓰인 곳
- 비밀정보(토큰 · 키 · 내부 URL) 포함 여부
- 기존 경고 · 제약이 사라졌는지
- 독자가 막힐 단계
- `rules/writing.md` 패턴 (강조하는 척 · 3개 나열 · 대시 · 장식 볼드 · 문서가 자기 얘기) — "문체 다듬어줘" 요청이면 그 문서 7절 순서로 진행

## 5. 반영 · 보고

- 검토를 통과한 내용만 반영한다. 큰 변경(README 구조 변경, 문서 삭제)은 초안을 보여 주고 승인을 받는다.
- 보고: 바뀐 문서, 근거 파일, "확인 필요"로 남은 항목, 사용자가 채워야 할 것.

## 하지 않는 것

- 코드 · 설정 파일 수정
- 코드에 없는 기능 서술, 추정을 사실처럼 쓰기
- 비밀정보 · 실제 계정 · 고객 데이터 포함
- 기존 문서의 경고 삭제
- `.env`를 읽어 환경변수 설명 작성 (`.env.example`과 `settings.py`만 근거로)
