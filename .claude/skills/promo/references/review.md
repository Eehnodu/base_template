# 최종 검수

`/promo` 7단계에서 검수 서브에이전트에게 넘기는 기준이다. 검수자는 만드는 과정에 참여하지 않았고, 만든 쪽의 이유 · 변명 · 수정 이력 · 예상 결론을 받지 않는다.

출처: video-shotcraft `references/final-review.md` (Apache-2.0). 샷 카드 · 갤러리 대조 항목을 우리 `techniques.md` 대조로 바꿔 다시 썼다.

## 받는 것

- 최신 영상 두 판(음악 · 음악 없음)과 장면마다 뽑은 프레임(등장 중 · 동작 절정 · 자리 잡은 뒤), 컨택트 시트
- `plan.md`: 브리프 · 꼭 보일 기능 · 결정표 · 시각 방향과 움직임 토큰 · 스타일프레임(또는 건너뛴 이유) · 기능-장면 배정 · 장면표 · 효과음표 · 데이터 규칙
- 고른 기법의 `techniques.md` 항목
- `craft.md`

빠진 입력이 있으면 그 항목은 "확인 못 함"으로 둔다. 기준을 짐작으로 채우지 않는다. 문서끼리 맞지 않으면 어느 문서의 어느 부분이 충돌하는지 적고 한쪽을 골라 정답으로 삼지 않는다.

## 확인 항목

### P 제품 목표

- P1 제품이 무엇이고, 누구를 위한 것이고, 핵심 장점이 무엇인지 분명한가
- P2 주의가 브리프의 기능 우선순위에 가 있는가
- P3 프로젝트에 없는 기능, 확인되지 않은 기능, 오해를 부르는 기능 주장이 있는가
- P4 결정표의 선택이 장면표 · 문구 · 화면 상태 · 소리 · 소재에 실제로 반영됐는가

### F 기능

- F1 꼭 보일 기능마다 알아볼 수 있는 장면이 하나 이상 있는가
- F2 장면마다 새 정보가 있는가. 같은 기능 · 같은 표어가 반복되는가
- F3 화면 상태가 기능을 이해시키는가, 장식 움직임에 그치는가

### V 시각 방향

- V1 글꼴 · 색 · 질감 · 모서리 · 빛 · 정보 밀도가 정한 방향과 맞는가
- V2 속도 · 튕김 · 정지 · 에너지 곡선이 움직임 토큰과 맞는가
- V3 정한 방향과 무관한 스타일(네온 · 사이버 등)로 흘렀는가
- V4 금지한 색 · 효과가 쓰였는가

### T 기법

- T1 기능-장면 배정의 기법이 해당 장면에 실제로 나오는가
- T2 기법의 핵심 길이 · 이징 관계 · 순서가 지켜졌는가 (픽셀 단위 일치는 요구하지 않는다)
- T3 기법의 "함정"을 어겼는가
- T4 한 기법이 두 번 이상 주인공으로 나오는가

### B 장면표

- B1 장면 순서 · 길이 · 기능이 장면표와 같은가
- B2 주 동작 · 화면 상태 · 소재 출처 · 자막 · 전환 · 효과음이 장면표와 같은가
- B3 로고 정지가 1초 이상인가, 여러 요소가 들어온 뒤 0.5초 이상 멈추는가
- B4 장면표 확정 뒤 근거 없이 핵심 장면이 빠지거나 바뀌거나 늘었는가

### D 데이터 · 소재

- D1 데이터 규칙(실제 공개 / 가짜 / 가림)을 지켰는가
- D2 실제 사용자 이름 · 닉네임 · 이메일 · 기록 · 내부 주소 · 키가 보이는가
- D3 있는 화면을 실제 캡처 대신 어설프게 다시 그렸는가
- D4 캡처에 글꼴 · 이미지 · 데이터가 다 로드됐는가 (스켈레톤 · 빈 칸 · 깨진 글꼴)

### A 소리

- A1 음악이 정한 방향과 맞고, 효과음이 들어갈 자리를 남기는가
- A2 효과음이 실제 동작 프레임에 맞는가. 눈에 띄게 어긋난 곳이 있는가
- A3 박자에 맞춘 장면의 컷 오차가 3프레임 이하인가
- A4 끝맺음(상승 → 쿵 → 빛)이 있는가 (장면표에 넣었다면)
- A5 긴 소리가 동작이 끝난 뒤에도 울리는가
- A6 렌더 결과에서 효과음이 다 들리는가, 찢어지는 소리가 있는가
- A7 합성 알림음 같은 음색이 이유 없이 쓰였는가
- A8 음악 없는 판이 같은 시간표에서 나왔는가 (화면 · 효과음이 프레임 단위로 같음)
- A9 출력 지연을 실측해 보정했고, 값과 잰 방법이 `plan.md`에 있는가

### Q 화면 품질

`craft.md` Q · R 전부. 적어도 글자 선명도 · 글자 크기(렌더 픽셀) · 구도 · 둥근 모서리 자르기 · 요소가 실제 자리에 앉는지 · 떨림 · 전환 이음매 · 싼 티 나는 빛 · 읽을 시간 · 화면 전체 충격 횟수 · 같은 프레임을 두 번 찍었을 때 같은지(결정적 렌더).

## 보고 형식

항목마다 번호와 근거 프레임:

```text
P1 통과  제품 정의와 핵심 장점이 오프닝 3초 안에 나온다.
F1 실패  기능 "기록 보기"가 어떤 장면에도 없다 (장면표 #6 에는 있음).
V3 실패  420프레임: 네온 보라 테두리가 정한 차분한 방향과 다르다.
T3 실패  515프레임: 휩팬 최고 속도가 낮아 이음매가 보인다 (기법 함정).
Q11 실패 615프레임: 보조 문구 렌더 높이 24px (하한 32px). work/qa/f615.png
```

끝에 세 묶음으로 정리한다: 반드시 고칠 것(심각도순) · 권장 · 확인 못 함. 증거 없는 "전체적으로 좋음"으로 대신하지 않는다. 보고를 좋게 보이려고 전부 통과로 두지 않는다.
