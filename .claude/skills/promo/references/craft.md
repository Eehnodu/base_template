# 영상 만들기 규칙

`/promo` 1단계 전에 읽고, 5단계 동안 계속 대조한다. 검수 서브에이전트도 이 파일로 판정한다.

출처: video-shotcraft `references/aesthetic-rules.md` · `references/pipeline.md` (Apache-2.0). 원문은 실제 제작에서 사용자가 지적한 사례를 규칙으로 만든 것이다. 3D(WebGL) 전용 규칙은 뺐고, 나머지를 HTML 프레임 렌더 기준으로 다시 썼다. 번호(R1 등)는 원문 번호를 그대로 둬서 대조할 수 있게 했다.

## 움직임 성격

감으로 이징 · 길이를 고르지 않는다. 제품을 두 축에 놓고 가장 가까운 행에서 시작한다.

- 에너지 축: 낮음(차분 · 고급 · 기관) ↔ 높음(운동 · 스타트업 · 오락). 길이 · 튕김 · 찌그러짐 크기를 정한다.
- 진지함 축: 진지(금융 · 의료 · 기업) ↔ 경쾌(소비자 · 소셜 · 아이). 경로가 곧은지 휘는지, 곁동작이 얼마나 많은지를 정한다.
- 근거는 제품 화면이다 (날카로운 모서리 → 공학적, 둥근 모서리 + 밝은 색 → 부드럽고 경쾌). 사용자가 말한 브랜드 성격이 화면 추정보다 우선.

| 성격 (예) | 기본 길이 @30fps | 등장 이징 | 튕김 | 찌그러짐 |
| --------- | ---------------- | --------- | ---- | -------- |
| 신뢰 (핀테크 · B2B) | 약 21f | `cubic-bezier(0,0,0.2,1)` | 1.0 없음 | 0 |
| 고급 (명품 · 패션) | 약 48f | `cubic-bezier(0.4,0,0.6,1)` | 1.02 이하 | 0 |
| 대담 (스포츠 · 게임 · 스타트업) | 약 18f | `cubic-bezier(0.16,1,0.3,1)` | 1.12 | 0.25 |
| 경쾌 (소비자 · 소셜) | 약 27f | `cubic-bezier(0.34,1.56,0.64,1)` | 1.08 | 0.18 |
| 차분 (건강 · 교육) | 약 42f | 대칭 ease-in-out | 1.0 | 0.04 이하 |
| 친근 (소상공인 · 커뮤니티) | 약 26f | `cubic-bezier(0.25,0.46,0.45,0.94)` | 1.04 | 0.08 |

확인 두 가지: 완성 영상의 움직임을 세 단어로 말했을 때 브랜드 성격과 맞는가. 등장 · 전환 · 정지가 같은 토큰 한 벌을 쓰는가 (두 벌이 섞이면 짜깁기처럼 보인다). "신뢰는 튕기지 않는다"는 착지가 없는 페이드 · 밀기 동작 얘기다. 착지해서 튕겨야 하는 장면은 성격과 상관없이 이징 y1 > 1.

## 속도 · 정지 (R)

- **R1 정보가 자리 잡으면 숨 쉰다.** 정보를 담은 요소(글자 카드 · 숫자 · 격자 전체)는 자리 잡은 뒤 1초 이상 멈춘 다음 넘긴다. 이 멈춤은 일반 카드보다 브랜드(로고가 자리 잡는 순간)에 먼저 준다.
- **R2 빠른 느낌은 가속도에서 나온다.** 등속 이동은 싸구려 슬라이드처럼 보인다. 날아오기 · 스크롤은 비선형 이징 + 고르지 않은 간격. 같은 요소가 많이 들어올 때는 "점점 빨라지는" 리듬에 물리 비유(카드 돌리기 등)를 붙이고, 다 채운 뒤 0.5초 멈춘다.
- **R3 느린 쪽이 낫다.** 첫 판은 거의 항상 빠르다. 오프닝의 주 동작은 3초 이상 이어지는 한 줄기로. 타이핑 · 필터 · 클릭 흉내는 실제 사람 속도로 해서 보는 사람이 따라 해 볼 수 있게. 시간표에 정지 시간을 먼저 넣는다. 원문 기록상 "너무 빠르다"는 늘 다시 만들었고 "느리게 바꾼 것"이 거부된 적은 없다.
- **R4 화면 전체 충격은 3번까지.** 화면 전체 확대 · 흔들기 · 번쩍임 · 반전 프레임은 영상 전체에서 3번 이하, 서로 충분히 떨어뜨린다. 나머지 박자 강조는 주인공 요소에만. 기법 하나를 한 번 쓴 것을 1번으로 센다 (내부에서 세 번 번쩍여도 1번).

## 화면 · 구도 (Q)

- **Q1 있는 화면은 실제 캡처.** 제품에 이미 있는 화면은 헤드리스 브라우저로 찍은 것(전체 + 요소 컷아웃 + 좌표)을 쓴다. 손으로 다시 그리는 건 화면에 없는 요소만, 그것도 실제 제품 수준일 때만. 데이터 규칙은 손으로 그린 소재에도 똑같이 적용한다.
- **Q2 글자가 흐리면 소재 해상도부터 본다.** `transform: scale()`로 키우면 크롬이 작게 그린 뒤 늘려서 흐려진다. 2배(필요하면 핵심 요소만 4배)로 찍은 소재를 줄여 쓰고, 화면 자체를 키울 때는 CSS `zoom`을 쓴다. `zoom`을 쓰면 좌표를 그만큼 다시 계산해야 초점이 안 어긋난다.
- **Q3 카메라는 흔들지 않는다.** 밝은 UI 소개 영상에 손떨림 흔들기 금지.
- **Q4 반짝임은 아낀다.** 광택이 지나가는 효과는 여러 요소에 뿌리지 않고, 한 장면에서 주인공에 한 번만. 반드시 그 요소의 둥근 모서리 안으로 잘라 낸다 (`overflow:hidden` + `border-radius`). 모서리 밖으로 새는 빛이 싸구려의 대표 신호다.
- **Q5 오프닝 주인공은 하나.** 여러 요소가 같이 춤추는 것보다 하나가 끝까지 이어지는 동작(비춤 → 다가감 → 떠오름 → 테두리 빛 → 제자리)이 첫인상을 만든다.
- **Q6 시점은 읽기 좋게.** 목록 · 쌓기처럼 정보가 많은 장면은 정면. 기울인 시점은 장면마다 따로 판단하고 영상 전체에 일괄 적용하지 않는다.
- **Q8 마무리는 단체 사진.** 기능이 여러 개인 제품은 지금까지 나온 기능의 대표 요소가 사방에서 날아와 로고를 둘러싸고 멈춘다. 영상 전체에서 에너지가 가장 높아야 한다. 첫 판의 마무리는 거의 항상 소극적이니 한 단계 올린다.
- **Q9 날아온 요소는 실제 자리에 앉는다.** 끝점은 페이지 레이아웃의 실제 칸(`layout.json` 좌표)이다. 페이지 위에 떠 있으면 가짜처럼 보인다.
- **Q10 문서류 화면은 꽉 채운다.** 보는 사람은 화면의 글자를 다 읽는다. 문서 · 보고서 장면은 제품의 실제 서식에 실제 밀도의 가짜 내용을 채우고, 사이드바 · 댓글 같은 주변 요소도 다 보이게 한다.
- **Q11 읽는 글은 크기 하한이 있다.** 1080p 기준 장면 자막은 렌더된 글자 높이 56px 이상(프레임 높이의 5% 이상, 60px 권장), 보조 문구 · 숫자 · 주소는 32px 이상. CSS `font-size`가 아니라 찍힌 프레임의 실제 픽셀로 잰다 (조상 요소의 배율까지 곱한 값). 글자는 두 상태뿐이다. 질감(흐리고 어둡게 해서 읽지 않게)이거나 읽는 글(크기 · 대비 충족, 밝은 배경 위면 그림자 · 깔개). 읽히지도 숨지도 않는 중간 상태는 지운다. 마지막 주소 · 행동 문구가 가장 작아지면 안 된다. 자체 확인: 자막 있는 장면마다 한 프레임을 480px 폭으로 줄여 휴대폰 미리보기에서도 읽히는지 본다.

## 소리 (S)

- **S1 영상 종류에 맞는 소리.** 소개 영상의 효과음은 휙(이동) · 쿵(착지) · 상승(쌓기) · 빛(반짝임) · 전환. 게임 효과음 같은 합성 소리는 피한다. 피하는 건 음색이지 동작이 아니다. 음악은 박자가 분명한 전자음 계열이 기본이고, 후보는 영상에 깔아서 들어 본다 (음악만 따로 들어서는 판단이 안 된다).
- **S2 효과음은 표로 관리.** `시점 + 소리 + 음량`을 표 한 곳에 모으고 줄마다 어떤 화면 동작인지 적는다. 연속 효과음은 두 소리 번갈아 · 음량 계단식 감소 · 간격을 화면 곡선에 맞춰 좁히기. 음 높이를 바꿔서 해결하지 않는다.
- **S3 소리는 화면이 확정된 뒤.** 장면 길이 · 순서를 바꾸는 수정은 끝에 반드시 "효과음표 전체 다시 맞추기"가 따라온다.
- **S4 실제 동작의 소리가 먼저.** 타이핑 화면엔 키보드 소리, 하나씩 떨어지면 하나씩 톡. 범용 휙 소리로는 안 된다. 긴 소리는 동작 길이만큼 자른다.
- **S5 싱크 보정 두 가지.** 출력 단계 지연(AAC 앞 덧댐, 48kHz 에서 2048샘플 ≈ 30fps 기준 1.28프레임이 전형)은 렌더 방식마다 실측해서 시점 계산에서 한꺼번에 뺀다. 소리 파일 자체의 지연(정점이 파일 맨 앞에 있지 않음)은 파일마다 잰다. `시작 = 목표 정점 프레임 − 파일 정점 지연 − 출력 지연`. 보정하지 않으면 두 지연이 쌓여 가장 센 타격이 0.27초 늦게 들린 사례가 있다. 박자에 맞춘 장면은 2~3프레임만 어긋나도 이유 없는 떨림처럼 보인다.
- 음량은 비율이다. 소리 파일의 정점이 0dB 가까이일 때 0.2~0.6 이 맞고, 작게 녹음된 소리는 1.0 을 줘도 음악에 묻힌다. 다른 소리로 바꾸거나 미리 정규화하고, 렌더 결과에서 `volumedetect`로 들리는지 · 찢어지지 않는지 확인한다.

## 문구 (C)

- **C1 문구는 화면이 확정된 뒤 다시 쓴다.** 첫 문구는 자리표시다. 최종 화면을 장면마다 보며 다시 쓴다. 애니메이션만 있는 장면에도 짧은 설명 자막을 단다 (브랜드 마무리 장면은 깔끔하게 비워 둔다).
- **C2 표어는 구체적으로.** "누가 + 기능 이름 + 구체적 이득". 뭉뚱그린 비유어는 구체어로 바꾼다. 중요한 기능이 나오기 전에 안내 글자 카드를 둔다.
- 화면 문구는 `rules/frontend/copy.md` (client 해요체), 범용 문구 금지는 `rules/writing.md` 3절, 이모지 금지.

## 진행 (P)

- **P1 첫 확인을 사용자에게 넘기지 않는다.** 고칠 때마다 직접 렌더하고 프레임을 뽑아 본다 (구도 · 떨림 · 글자 선명도 · 이음매). 필요하면 잘라 확대하거나 두 프레임의 차이를 본다.
- **P2 참고 소재는 기법 목록으로 쪼갠다.** 참고 영상은 프레임을 뽑아 기법마다 구현 방식을 적고, 장면마다 맞는지 판단한다. 참고 이미지는 "그런 종류의 장면" 느낌이지 영상 전체의 스타일 지시가 아니다.
- **P3 애매한 지적은 대상부터 확인.** "첫 번째 제목"이 어느 것인지 먼저 묻는다. 잘못 고쳤으면 그 위에 덧대지 말고 되돌린 뒤 다시 한다.
- **P4 기능 목록 → 장면.** 핵심 기능이 빠지면 다시 만든다. 한 기법은 영상 전체에서 한 번만 주인공. "이 장면이 새로 알려 주는 게 뭔가"로 걸러서 같은 소재 · 같은 정보는 한 번만.
