$ARGUMENTS 기능을 백엔드와 프론트에 함께 구현한다. CLAUDE.md의 "작업 흐름"과 "완료 기준"을 따른다. 백엔드를 먼저 끝내고 프론트로 넘어간다.

## 입력

- 필수: 기능 설명 (`$ARGUMENTS`)
- 있으면 좋은 것: 배경, admin · client 구분, 비범위, 제약, 수용 기준, 실패 처리 방식

## 1. 요청 정리

요청을 **목표 · 배경 · 범위 · 비범위 · 제약 · 수용 기준(Given / When / Then)**으로 정리한다. 빠졌거나 모호하면 질문한다. 실패 상황의 처리(권한 없음 · 중복 · 대상 없음이 화면에 어떻게 보이는지)도 정한다.

## 2. 조사

**be-researcher**와 **fe-researcher**를 호출해 백엔드 · 프론트 관련 코드를 조사한다. 서로 독립적이므로 함께 돌려도 된다.

## 3. 계획

아래를 정리해 보여 준다. 파일은 아직 고치지 않는다.

- **API 계약**: 메서드, 경로, 로그인 필요 여부, 요청 · 응답 필드, 에러 코드와 상태. 백엔드와 프론트는 이 계약을 기준으로 만든다. 계약이 바뀌면 즉시 보고에 적는다.
- 백엔드 · 프론트 각각 만들 · 고칠 파일 (write set이 겹치지 않게)
- 모델 변경 여부와 마이그레이션 필요 여부
- 화면 상태 (로딩 · 데이터 · 빈 목록 · 에러)
- **검증이 안 다루는 실패 모드 상위 3개** (권한 없는 사용자, 대상 없음, 중복, 빈 입력, 동시 요청 등)와 각각 어느 단계에서 어떻게 확인할지
- 위험 요소, 사용자에게 할 질문

**DB 모델 변경, 인증 · 권한 변경, 새 의존성, 공개 API 변경, 모호한 요구사항**이 있으면 여기서 멈추고 승인을 받는다. 없으면 계획을 알리고 진행한다. 풀스택은 보통 계획이 크므로 **백엔드 단계를 먼저 승인받고, 백엔드 결과를 보고한 뒤 프론트로** 간다.

## 4. 실행 — 백엔드

1. **be-db-modeler** 호출 → 모델 작성 (모델 변경이 없으면 건너뛴다)
2. **be-api-builder** 호출 → repository · service · router 작성, 등록
3. **`/verify backend`** — 여기서 통과해야 프론트로 넘어간다

## 5. 실행 — 프론트

4. **fe-ui-builder** 호출 → 컴포넌트 · 컨테이너 작성
5. **fe-api-connector** 호출 → API 연동과 타입 정의. 3단계의 API 계약과 실제 백엔드 코드가 다르면 백엔드 코드를 기준으로 맞추고 **계약 변경**으로 보고한다.
6. **`/verify all`** — 백엔드 + 프론트 전체(빌드 포함) + **계약 대조**(프론트가 부르는 경로 · 필드 · 에러 코드가 백엔드와 맞는지). 프론트 단계에서 백엔드를 손댔어도 여기서 다시 잡힌다.

실패하면 최초 원인만 고치고 다시 `/verify`. 같은 실패가 두 번 반복되면 멈추고 보고한다.

7. **`/review`** — 인증 · 권한 · 입력 처리가 들어간 기능은 반드시. 그 외에도 기능을 마무리할 때 한 번 거친다.
8. **`/audit`** — 새 화면 · 바뀐 화면이 있으면 화면 단위 감사(접근성 · 상태 · 폼 · 반응형 · 모션 · 문구). 브라우저 확인 목록은 보고에 넘긴다.

## 6. 기록 · 보고

- CLAUDE.md의 "작업 기록" 규칙대로 `zz_docs/`를 갱신한다. LOGIC.md(모듈 · API · 에러 코드)도 반영한다.
- 완료 기준대로 보고한다: 변경 파일(백엔드 / 프론트)과 이유, 동작 변경, API 목록, **계획한 API 계약에서 바뀐 것**, 검증 결과(못 돌린 것 · 브라우저 미확인 포함), 수용 기준 충족 여부, 묻지 않고 내린 결정, 범위 밖 변경, 남은 위험.
- 마이그레이션이 필요하면 `./migrate.sh "메시지"` 실행이 필요하다고 알린다.

## 하지 않는 것

- 계약 없이 백엔드와 프론트를 각자 추정으로 만들기
- 같은 파일을 두 에이전트가 동시에 수정
- `/verify backend`를 통과하지 않은 채 프론트 진행
- 마이그레이션 실행, 요청 범위 밖 리팩터링, 검증 약화
