$ARGUMENTS 문제를 수정한다. CLAUDE.md의 "작업 흐름"과 "완료 기준"을 따른다. **버그 수정과 리팩터링을 섞지 않는다.**

```
원인을 코드에서 확정하기 전에는 수정하지 않는다.
```

1~3단계(조사)만 필요하면 `/debug`를 쓴다. 이 스킬의 1~3단계는 `/debug`와 같다.

## 입력

- 필수: 증상 (`$ARGUMENTS`)
- 있으면 좋은 것: 기대 동작 / 실제 동작, 재현 절차, 오류 메시지 · 로그, 최근 변경, 환경(브라우저 · 브랜치)

## 1. 증상 정리

다음을 정리한다. 빠진 항목이 판단에 꼭 필요하면 질문하고, 아니면 "모름"으로 두고 진행한다.

- 증상, 기대 동작 / 실제 동작
- 재현 절차, 환경
- 오류 메시지 · 로그 — **최초 실패 지점**을 찾고 파생 오류와 구분한다. 비밀 값이 있으면 `[redacted]`로 가린다.
- 최근 변경 (`git log --oneline -10`, `git diff`로 확인)

**재현 가능성을 먼저 판단한다**: 재현 절차가 있고 코드로 따라갈 수 있는가, 간헐적인가(타이밍 · 캐시 · 세션), 환경 의존인가. 재현할 수 없으면 그 사실과 확인이 필요한 정보를 먼저 알린다.

## 2. 조사

증상이 백엔드 쪽인지 프론트 쪽인지 판단해 **be-researcher** 또는 **fe-researcher**를 호출한다. 애매하면 둘 다. 증상과 관련된 폴더만 좁게 읽게 한다.

## 3. 원인 좁히기

원인 후보를 **3개 이하**로 표로 정리한다. 파일은 아직 고치지 않는다.

| 후보 | 근거 | 확인 위치 (파일:줄) | 맞다면 보일 증거 | 아니라면 배제할 증거 |
| ---- | ---- | ------------------- | ---------------- | -------------------- |

후보를 좁히는 방법:

- **동작하는 비슷한 코드**를 찾아 차이를 전부 나열한다 (같은 패턴의 다른 화면 · 다른 라우터). 차이 중 하나가 원인일 때가 많다.
- 프론트 → API → 서비스 → DB처럼 **경계가 여러 개**면 어느 경계에서 깨지는지 먼저 확정한다: 각 경계의 입력 · 출력을 로그나 네트워크 탭으로 한 번 확인한다. 경계를 모르는 채 한쪽만 고치지 않는다.
- 가설은 한 번에 하나. 검증해서 틀리면 그 위에 덧붙이지 말고 새 가설로 간다.

코드에서 원인을 확정한다. **확정하지 못하면 멈추고** 확인한 것과 남은 가능성, 다음에 확인할 가장 작은 방법을 알린다. 추측으로 고치지 않는다.

## 4. 수정

- **확정한 원인 하나만** 고친다. 관련 없는 코드 · 포맷 · 이름은 건드리지 않는다.
- 수정이 인증 · 권한 · DB · 공개 API에 닿거나 여러 파일로 번지면 수정 계획을 보여 주고 승인을 받는다.
- 증상만 덮는 수정(예외 삼키기, 조건 하나 우회)인지 원인을 고치는 수정인지 구분해서 적는다. 증상만 덮어야 한다면 이유와 후속 작업을 남긴다.

## 5. 검증

- **`/verify backend`** 또는 **`/verify frontend`**(둘 다 고쳤으면 `/verify all`)로 검증한다.
- 재현 절차로 증상이 사라졌는지 확인한다. 못 했으면 사용자가 확인할 절차와 기대 결과를 적는다.
- 같은 원인이 다른 곳에도 있는지 Grep으로 확인한다. 있으면 고치지 말고 보고에 적는다 (범위 밖).
- **수정을 3번 시도해도 증상이 남으면 멈춘다.** 가설 · 시도 · 결과를 표로 정리해 사용자와 논의한다. 더 시도하는 것은 접근이 틀렸다는 신호를 무시하는 것이다.

## 6. 기록 · 보고

- CLAUDE.md의 "작업 기록" 규칙대로 `zz_docs/`를 갱신한다.
- 보고: 원인(파일:줄과 한두 문장), 고친 파일과 변경 내용, 동작 변경, 검증 결과(못 돌린 것 포함), 묻지 않고 내린 결정, 같은 원인으로 생길 수 있는 다른 문제, 재발 방지에 필요한 테스트 케이스(Given / When / Then).

## 하지 않는 것

- 원인을 확정하지 않은 채 수정
- 여러 후보를 한 번에 고치기
- 검증 약화(`any` 우회, `eslint-disable`, 예외 삼키기, 테스트 삭제)로 증상 감추기
- 버그 수정에 리팩터링 · 포맷 변경 섞기
- 사용자가 만든 변경 되돌리기
