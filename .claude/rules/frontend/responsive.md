# 반응형 기준 (휴대폰 · 패드 · 데스크톱)

화면은 휴대폰 · 패드 · 데스크톱 모두에서 같은 작업을 끝낼 수 있어야 한다. 휴대폰 배치를 먼저 정하고 넓혀 간다. 색 · 위계는 `design.md`, 화면 품질 확인은 `conventions.md` 가 기준이고 이 문서는 폭 · 입력 방식 · 기기 차이를 정한다.

## 1. 구간

Tailwind 기본 구간을 쓴다. 새 구간(`screens`)을 만들지 않는다.

| 구간 | 폭 | 대표 기기 | 기본 배치 |
| ---- | -- | --------- | --------- |
| 기본 (접두사 없음) | 0 ~ 639px | 휴대폰 세로 (360 · 390 · 412) | 1열, 햄버거 메뉴, 버튼은 폭을 채움 |
| `sm:` | 640 ~ 767px | 휴대폰 가로 · 작은 패드 | 1 ~ 2열 |
| `md:` | 768 ~ 1023px | 패드 세로 (768 · 820 · 834) | 2열까지, 메뉴는 여전히 햄버거 |
| `lg:` | 1024 ~ 1279px | 패드 가로 · 작은 노트북 | 가로 메뉴 · 사이드바가 펼쳐진다 |
| `xl:` | 1280px ~ | 데스크톱 | 본문 최대 폭 안에서 여백만 늘린다 |

- 클래스는 휴대폰 값을 먼저 쓰고 `sm:` · `md:` · `lg:` 로 넓힌다 (`flex-col lg:flex-row`). `max-*:` 로 거꾸로 줄이지 않는다.
- 패드는 폭이 넓어도 손가락으로 조작한다. `md:` 에서 데스크톱 배치를 미리 꺼내지 않는다. 가로 메뉴 · 마우스 전제 조작은 `lg:` 부터.
- 본문은 `max-w-*` 로 최대 폭을 정하고 가운데 둔다. 고정 폭(`w-[…px]`)으로 화면을 짜지 않는다.

## 2. 배치가 바뀌는 부분

| 요소 | 휴대폰 · 패드 (lg 미만) | 데스크톱 (lg 이상) |
| ---- | ---------------------- | ------------------ |
| 주 메뉴 | 햄버거 서랍. 계정(프로필 · 로그아웃)도 서랍 안 | 헤더 가로 메뉴 |
| admin 사이드바 | 접어 두고 버튼으로 연다 | 펼친 채 고정 |
| 표 | 감싸는 쪽에 `overflow-x-auto` (가로 스크롤), 열이 많으면 카드 목록으로 바꾼다 | 표 |
| 카드 격자 | 1열 → `sm:grid-cols-2` | `lg:grid-cols-3` 이상 |
| 모달 | 좌우 16px 여백으로 폭을 채우고, 내용이 길면 본문만 스크롤 · 버튼은 아래에 고정 | 가운데 고정 폭 |
| 필터 · 정렬 | 한 줄 가로 스크롤 칩 또는 "필터" 버튼 뒤로 접기 | 펼쳐 놓기 |
| 탭 · 칩 줄 | 넘치면 가로 스크롤(`overflow-x-auto`), 줄바꿈해서 높이가 들쭉날쭉하지 않게 | 한 줄 |
| 두 칸 나란히 (목록 + 상세 등) | 위아래로 쌓고, 중요한 쪽을 위에 | 좌우 |

- 숨겨도 되는 것은 장식뿐이다. 기능 · 정보를 `hidden lg:block` 으로 휴대폰에서 없애지 않는다. 자리가 없으면 서랍 · 접기 · 다음 화면으로 옮긴다.
- 휴대폰의 글자 · 칩 · 간격은 한 단계 작게 시작하고 `lg:` 에서 키울 수 있다. 본문은 14px 아래로 내리지 않는다 (`design.md` 2절).

## 3. 터치 · 마우스 없음

- 마우스를 올려야(hover) 보이는 버튼 · 메뉴 · 설명을 만들지 않는다. 패드 · 휴대폰에는 hover 가 없다. hover 는 꾸밈(색 변화)으로만 쓰고, 기능은 항상 보이거나 눌러서 연다. hover 에서만 보이게 해야 하면 `[@media(hover:hover)]:` 로 감싸고 터치 화면에서는 늘 보이게 한다.
- 손가락 영역은 44×44px (client 규칙에서 40px 하한을 정했으면 그것을 따른다). 눌리는 것끼리는 8px 이상 띄운다.
- 길게 누르기 · 스와이프 · 두 손가락 동작만으로 되는 기능을 두지 않는다. 같은 일을 하는 버튼을 함께 둔다.
- 키보드 단축키 · Esc 안내 같은 키보드 전용 문구는 `[@media(pointer:fine)]:block` 처럼 마우스 · 키보드 기기에서만 보인다.

## 4. 입력과 가상 키보드

- 입력칸 글자는 16px(`text-base`) 이상. 작으면 iOS 가 화면을 확대한다.
- 입력 종류를 알린다: `type="email" · "tel" · "url" · "search"`, 숫자는 `inputMode="numeric"`, 제출 키는 `enterKeyHint`, 자동 완성은 `autoComplete`.
- 가상 키보드가 화면 아래 절반을 가린다. 화면 높이는 `h-screen` 대신 `h-dvh` · `min-h-dvh`. 아래에 고정한 버튼 · 입력줄이 키보드에 가려지지 않는지 휴대폰에서 본다. 입력칸을 누르면 그 칸이 보이게 스크롤되는지도.
- 한글 입력(IME) 조합 중 Enter 는 바로 제출하지 않는다 (`compositionend` 뒤에 제출).

## 5. 안전 영역 · 방향

- 화면 위아래에 고정한 요소(하단 탭 · 하단 버튼 · 전체 화면 무대)는 노치 · 홈 표시줄에 가리지 않게 `pb-[env(safe-area-inset-bottom)]` · `pt-[env(safe-area-inset-top)]` 를 준다. `index.html` 의 viewport 에 `viewport-fit=cover` 가 있어야 값이 들어온다. 이 임의값은 토큰 규칙의 예외로 허용한다.
- 휴대폰 가로(높이 약 360 ~ 430px)에서 세로 가운데 정렬한 큰 화면 · 위아래 고정 요소가 겹치지 않는지 본다. 높이가 모자라면 스크롤되게 둔다 (`overflow-hidden` 으로 자르지 않는다).
- 패드는 돌릴 수 있다. 세로(768) · 가로(1024) 둘 다 본다.

## 6. 이미지 · 미디어 · 긴 글

- 이미지 · 썸네일은 `aspect-*` 로 비율을 고정해 불러오는 동안 화면이 튀지 않게 한다. 목록의 이미지는 `loading="lazy"`.
- 긴 이름 · 제목은 `truncate` 또는 `line-clamp-*`, 한글 줄바꿈은 `break-keep`. 숫자 · 날짜가 줄바꿈으로 갈라지지 않게 `whitespace-nowrap`.
- 가로 넘침 0: 어떤 폭에서도 페이지가 옆으로 밀리지 않아야 한다 (`document.documentElement.scrollWidth > window.innerWidth` 가 false).

## 7. 만들기 전에 (계획)

`design.md` 6절 와이어프레임을 두 개 그린다.

```
휴대폰 (360)            데스크톱 (1280)
┌──────────┐           ┌──────────────────────────┐
│ 헤더 ☰    │           │ 헤더  메뉴 메뉴     계정 │
│ 제목      │           │ 제목                    │
│ [필터 ▾]  │           │ 필터 칩 칩 칩 │ 목록      │
│ 카드      │           │              │ 카드 카드 │
│ 카드      │           │              │ 카드 카드 │
└──────────┘           └──────────────────────────┘
```

어떤 요소가 접히는지 · 서랍으로 가는지 · 순서가 바뀌는지를 계획에 적는다. 패드(768)가 둘 중 어느 쪽을 따르는지도 적는다.

## 8. 확인 방법

| 폭 × 높이 | 무엇을 보나 |
| --------- | ----------- |
| 360 × 740, 390 × 844 | 휴대폰 세로: 1열 · 버튼 폭 · 서랍 · 가상 키보드 · 가로 넘침 |
| 844 × 390 | 휴대폰 가로: 높이가 낮을 때 겹침 · 스크롤 |
| 768 × 1024 | 패드 세로: 2열 · 메뉴가 아직 햄버거인지 · 터치 영역 |
| 1024 × 768 | 패드 가로: 가로 메뉴로 바뀌는 경계, hover 없이 쓸 수 있는지 |
| 1280 × 800 | 데스크톱: 최대 폭 · 여백 |

- 라이트 · 다크 둘 다.
- 헤드리스 브라우저(CDP)로 볼 때는 `Emulation.setDeviceMetricsOverride` 에 `mobile: true`, 터치는 `Emulation.setTouchEmulationEnabled`. 실제 iOS Safari · Android Chrome 의 가상 키보드 · 안전 영역은 헤드리스로 확인되지 않으니 보고에 "브라우저 확인 필요"로 남긴다.

## 9. 확인 목록

- [ ] 휴대폰 배치를 먼저 정했고 `sm:` · `md:` · `lg:` 로 넓혔다 (고정 폭 화면 없음)
- [ ] 360 · 390 · 768 · 1024 · 1280 과 휴대폰 가로에서 가로 넘침 0, 겹침 · 잘림 없음
- [ ] 휴대폰 · 패드에서 숨긴 기능이 없다 (서랍 · 접기로 옮겼다)
- [ ] hover 로만 보이는 기능 없음, 손가락 영역 44px(또는 정한 하한), 간격 8px
- [ ] 입력칸 16px · 입력 종류 · 자동 완성, 가상 키보드가 입력줄 · 하단 버튼을 가리지 않는다
- [ ] 위아래 고정 요소에 안전 영역, `h-screen` 대신 `h-dvh`
- [ ] 표 · 탭 · 칩은 좁은 폭에서 가로 스크롤 또는 카드로 바뀐다
- [ ] 모달은 휴대폰에서 폭을 채우고 본문만 스크롤된다
