# 화면 디자인 기준

`components.md`(공통 컴포넌트)와 `conventions.md`(토큰 · 화면 품질)가 **우선**한다. 이 문서는 그 안에서 "어떻게 보이게 만들지"를 정한다. 토큰과 컴포넌트가 이미 정해져 있으니, 디자인 작업의 대부분은 **배치 · 위계 · 절제**다.

## 1. 만들기 전에 한 줄

화면을 그리기 전에 이 한 줄을 계획에 적는다:

```
이 화면은 [admin 관리 도구 / client 서비스 화면]이고, 사용자는 [누구]이며, 여기서 끝내야 하는 일은 [핵심 작업 1~2개]다. 밀도는 [높게 / 보통 / 낮게].
```

- **admin**: 관리 도구다. 밀도 높게, 표 · 폼 · 필터 중심, 장식 없음. 한 화면에서 많은 정보를 빠르게 훑는다.
- **client**: 서비스 화면이다. 밀도 보통, 한 화면에 핵심 작업 하나, 여백으로 위계를 만든다.

이 한 줄이 없으면 "그럴듯한 대시보드 템플릿"이 나온다.

## 2. 위계 — 크기보다 무게와 색

- 제목 · 본문 · 보조 텍스트 위계는 **글자 크기를 키우는 대신** `font-medium` · `font-semibold`와 `text-text-main` / `text-text-sub`로 만든다. 한 화면에 큰 제목은 하나.
- 본문은 `text-sm`(14px) 이상. `text-xs`(12px)는 보조 메타(날짜 · 개수)에만. 모바일에서 입력창 글자는 16px(`text-base`) — 작으면 iOS가 화면을 확대한다.
- 본문 줄 길이는 80자 안쪽 (`max-w-prose` 또는 `max-w-[65ch]`). 긴 문단은 `leading-relaxed`. 제목은 `text-balance`, 긴 단락은 `text-pretty`로 마지막 줄에 한 단어만 남는 것을 막는다 (Tailwind 3.4).
- 반경 · z-index를 새로 정하지 않는다. 반경은 같은 역할의 공통 컴포넌트 값(입력 · 버튼 `rounded-md`, 카드 `rounded-xl`, 뱃지 · 아바타 `rounded-full`)을 따르고 `rounded-[…]` 임의값을 만들지 않는다. z-index는 이미 쓰는 단계(10 · 20 · 40 · 50)만 쓰고, 모달 · 토스트보다 위로 올리지 않는다.
- 같은 줄에 놓인 카드는 높이를 맞추고 버튼 · 하단 요소를 정렬한다 (`flex flex-col` + `mt-auto`). 목록은 시작 Y를 맞춘다.
- 라벨을 대문자로 바꾸거나 자간을 벌리지 않는다. 있어도 되는 라벨은 없어도 된다 — 값만으로 뜻이 통하면 라벨을 지운다.
- **시각 구조는 정보다.** 테두리 · 구분선 · 번호 · 카드는 정보를 나누는 뜻이 있을 때만 쓴다. 순서가 있을 때만 번호를 붙이고, 모든 항목 앞에 점 · 아이콘을 다는 습관을 버린다.
- 변하는 숫자(카운트 · 금액 · 시간)는 `tabular-nums`, 경로 · ID · 코드는 `font-mono`.

## 3. 색 — 토큰 안에서

- 팔레트는 이미 `index.css`에 있다 (zinc 중립 + `primary` + 상태색 4개). **새 색을 만들지 않는다.** 토큰을 추가 · 변경해야 하면 `/palette`로 — 승인 뒤 `index.css`(라이트 · 다크 둘 다) → `tailwind.config.js` → `scripts/check_contrast.py` 쌍 추가 순.
- 텍스트 · 배경 쌍은 **라이트 · 다크 각각** WCAG AA(본문 4.5:1, 큰 글자 · UI 경계 · 포커스 링 3:1)를 지킨다. `frontend/`에서 `python scripts/check_contrast.py`로 확인한다. 다크모드는 수치가 통과해도 밝은 글자가 실제로는 더 약하게 보이므로 브라우저에서 한 번 본다.
- 강조색은 화면당 한 종류. `primary`는 주 행동(저장 · 확인)에만. 상태색(`success` · `error` · `warning` · `info`, `point-*`)은 상태를 알릴 때만 — 장식 · 강조로 재사용하지 않는다. 상태는 색과 함께 아이콘 · 문구를 병행한다 (빨강 ↔ 초록만으로 구분하면 남성 약 8%가 못 본다).
- 차트 · 뱃지처럼 색 여러 개가 인접하면 색끼리 3:1을 맞추려 하지 말고 **테두리 색 하나**를 두고 각 채움과 테두리가 3:1이 되게 한다.
- 배경 위계는 `bg` → `bg-card` → `bg-sub` 세 단계로 충분하다. 그림자는 떠 있는 것(모달 · 드롭다운 · 토스트)에만, 고정된 카드 · 표에는 `border-line`.
- 색만으로 뜻을 전하지 않는다 (`conventions.md` 화면 품질). 에러는 빨간 테두리 + 문구.

## 4. 모션 — 절제

- 상태 변화(hover · focus · 열림 · 닫힘)에는 짧은 `transition-colors` · `transition-opacity` · `transition-transform` (150~200ms). **`transition-all` 금지.**
- 페이지 · 섹션이 나타날 때 페이드 · 슬라이드 인을 넣지 않는다. 첫 로드에 애니메이션을 재생하지 않는다. 모든 카드에 hover 애니메이션을 달지 않는다.
- 반복 애니메이션은 로딩(`Skeleton` · `Loading`)에만. 새 keyframe을 만들면 `@media (prefers-reduced-motion: reduce)` 처리를 `index.css` 기존 패턴대로 붙인다.
- `top` · `left` · `width` · `height`를 애니메이션하지 않는다. `transform` · `opacity`만.
- 애니메이션마다 이유를 한 문장으로 말할 수 있어야 한다 ("열림을 알린다", "삭제됐음을 보인다"). 없으면 정적으로 둔다.

## 5. 피할 것 — 템플릿 · AI 냄새

아래가 보이면 "생각 없이 나온 기본값"이다. 하나라도 있으면 이유를 말할 수 있어야 한다.

- 크림색 배경 + 세리프 제목 + 테라코타 강조 / 검은 배경 + 형광색 강조 하나 / 신문 스타일 헤어라인 + 각진 모서리 + 빽빽한 칼럼
- 같은 모양 카드 3개 나열, 카드마다 아이콘 + 제목 + 설명, 카드 안에 카드
- 큰 제목에 gradient 텍스트, 배경 blob · glow, 장식용 gradient
- 대문자 자간 벌린 작은 라벨(eyebrow), 중점(·)으로 이어 붙인 메타 줄, 화살표 `→` 남발
- 순수 `#000` · `#fff` 직접 사용 (토큰을 쓰면 자동으로 피해진다)
- 자리 표시 데이터: "John Doe", `99.99%`, "Acme", "Lorem ipsum" — 실제 도메인의 예시 값을 쓴다
- 마케팅 문구: "손쉽게", "혁신적인", "최고의" — 화면 문구는 사용자가 할 일을 말한다
- 보라 · 파랑 글로우를 기본 강조색으로 (AI 기본값). 강조색은 `primary` 토큰 하나
- `h-screen` — 모바일 주소창에 아래가 잘린다. `h-dvh` · `min-h-dvh`. (기존 7곳은 화면 고칠 때 같이)
- `alert()` · `confirm()` · `prompt()` — 공통 `Modal` · `Toast`
- 문구: 성공 메시지의 느낌표("저장했습니다!"), "앗" · "이런", 한 화면에 반말 · 합니다체 혼용, 화면 문구 안의 대시(—)

## 6. 절차 — 토큰 · 배치 먼저, 코드는 나중

1. 1절의 한 줄 + 화면에 들어갈 정보를 **중요도 순으로** 나열한다.
2. 배치를 텍스트 와이어프레임(ASCII)으로 한 번 그린다. 360px에서 어떻게 접히는지도.
3. 쓸 공통 컴포넌트와 토큰을 정한다. 새 토큰 · 새 컴포넌트가 필요하면 여기서 승인. 새 패키지를 import하기 전에 `package.json`에 있는지 확인하고, 없으면 설치도 여기서 승인.
4. 1~3을 보고 "비슷한 프로젝트 기본값"이 아닌지 한 번 의심한다 — 5절 목록과 대조.
5. 그다음 코드. 네 가지 상태(로딩 · 데이터 · 빈 · 에러)와 접근성은 `conventions.md` 화면 품질대로.

## 7. 기존 화면을 고칠 때

"이 화면 다듬어줘"처럼 동작은 그대로 두고 보이는 것만 고칠 때. 재작성하지 않고 지금 스택 · 공통 컴포넌트 위에서 고친다.

1. **훑기.** 화면이 쓰는 컴포넌트 · 토큰 · 상태 처리를 파악한다. 공통 컴포넌트를 쓰지 않은 곳, 고정색, 임의값을 표시한다.
2. **진단.** 5절 목록과 8절 확인 목록으로 감사한다 (`/audit`이 이 단계다).
3. **고치기 — 이 순서로.** 효과가 큰 것부터: 위계(글자 무게 · 색) → 색 토큰 위반 → hover · active · focus 상태 → 간격 · 정렬(카드 하단 · 목록 Y) → 클리셰 컴포넌트 교체 → 로딩 · 빈 · 에러 상태 보강 → 문구.
4. **보존.** 스택 · 스타일 방식 · 공통 컴포넌트를 바꾸지 않는다. 한 번에 한 화면, 리뷰할 수 있는 크기로. 고칠 때마다 `/verify frontend`.

## 8. 확인 목록

`/design` · fe-ui-builder가 끝날 때, verifier가 볼 때:

- [ ] 1절 한 줄이 계획에 있다
- [ ] 큰 제목은 하나, 위계는 무게 · 색으로
- [ ] 강조색 한 종류, 새 hex 없음
- [ ] `transition-all` 없음, 첫 로드 애니메이션 없음
- [ ] 5절 패턴 없음 (있으면 이유가 적혀 있음)
- [ ] 예시 데이터가 실제 도메인 값
- [ ] 아이콘만 있는 버튼에 `aria-label`, 인터랙티브 요소는 손가락 크기(터치 영역 44×44px — 24px 아이콘이면 패딩 10px)
- [ ] Tab으로 옮겨 다닐 때 포커스 링이 보인다 (`focus-visible:` + `line-focus` 토큰). 공통 컴포넌트를 썼으면 컴포넌트가 책임진다
- [ ] 같은 줄 카드의 높이 · 버튼 위치가 맞는다
- [ ] 마무리 전 `/audit`으로 화면 단위 감사 (접근성 · 상태 · 폼 · 반응형 · 모션 · 문구)
