# 로딩 표시 기준

기다리는 시간에 따라 보여 줄 것이 다르다. 컴포넌트 위치와 props는 `components.md` "로딩 상태", 상태 네 가지(로딩 · 데이터 · 빈 · 에러)는 `conventions.md` 화면 품질이 기준이고, 이 문서는 **언제 무엇을** 쓸지를 정한다.

## 1. 대기 시간별 표시

| 예상 대기 | 사용자가 느끼는 것 | 보여 줄 것 | base 에서 쓸 것 |
| --------- | ------------------ | ---------- | ---------------- |
| 0.1초 미만 | 즉시 반응 | 아무것도 안 보여 준다 | — |
| 0.1 ~ 1초 | 지연을 느끼기 시작 | 누른 자리의 작은 표시 (버튼 비활성 · 스피너) | `Button disabled={mutation.isPending}`, 버튼 안 아이콘 회전. 화면 전체를 막아야 할 때만 `Loading` 오버레이 |
| 1 ~ 3초 | 기다리고 있음을 인지 | 스켈레톤 — 실제 레이아웃 자리를 먼저 그린다 | `PageSkeleton` · `Skeleton` (첫 조회 `isLoading`) |
| 3 ~ 10초 | 지루함 · 불안 | 진행률(몇 % · 5개 중 2개) 또는 단계 문구 | 공통 컴포넌트 없음. 필요하면 `ui/`에 새로 만든다 (승인 대상) |
| 10초 이상 | 오류로 의심 | 무슨 일을 하는지 · 예상 시간 · **취소**, 가능하면 백그라운드로 넘기기 | 스트리밍은 `useChatStream`의 `abort`. 일반 요청 취소는 공통 장치 없음 (확인 필요) |

- 예상 대기는 기능을 만들 때 정한다. 목록 · 상세 조회는 보통 1 ~ 3초 칸, 저장 · 삭제는 0.1 ~ 1초 칸, 생성형 AI · 파일 처리는 3초 이상 칸이다.
- 1초 미만 작업에 스켈레톤을 쓰지 않는다 — 화면이 깜빡여 오히려 눈이 피로하다.
- 3초 이상 걸리는 작업에 도는 아이콘만 두지 않는다 — 진행이 보이지 않으면 이탈한다.

## 2. 깜빡임 막기

- 스켈레톤 · 스피너는 요청 시작 후 **약 300ms 뒤에** 보이게 하고, 한 번 보이면 **약 500ms는 유지**한다. 빠른 응답에서 번쩍이고 사라지는 것을 막는다. 공통 훅은 아직 없다 (만들면 `hooks/common/`, 승인 대상).
- **다시 조회(refetch)할 때는 스켈레톤으로 덮지 않는다.** `useGet`은 이전 데이터를 유지하므로(`keepPreviousData`) 기존 화면을 그대로 두고, 필요하면 목록 위 작은 표시만 더한다. 스켈레톤은 처음 그릴 데이터가 없을 때(`isLoading`)만.
- 스켈레톤 블록은 실제 콘텐츠와 같은 크기 · 간격으로 조립해 데이터가 와도 레이아웃이 튀지 않게 한다 (`components.md`).

## 3. 움직임

- 로딩 표시는 미세하게라도 움직인다. 정지된 회색 화면은 멈춘 것으로 오해한다. 스켈레톤은 왼쪽에서 오른쪽으로 한 번 훑는 빛(`index.css`의 `.skeleton`)을 쓴다.
- 예외: 움직임 줄이기 설정(`prefers-reduced-motion: reduce`)에서는 반짝임을 끄고 정지 블록으로 둔다 (`.skeleton`에 이미 있다). 대신 아래 4절의 문구로 진행 중임을 알린다.
- 로딩 애니메이션을 새로 만들면 같은 설정 처리를 `index.css` 기존 패턴대로 붙인다 (`design.md` 4절).

## 4. 접근성

- 로딩 영역에 `role="status"`와 숨김 문구("불러오는 중")를 둔다. 스켈레톤 블록 자체는 `aria-hidden` (`Skeleton`이 이미 한다).
- 갱신되는 영역에는 `aria-busy="true"`를 로딩 동안만 건다.
- 끝났을 때도 알린다: 저장 성공 · 실패는 Toast (`conventions.md` 에러 처리).

## 5. 오래 걸리거나 실패할 때

- 무한히 로딩만 돌리지 않는다. **15 ~ 30초**가 지나면 로딩을 멈추고 `ErrorState`로 "응답이 늦습니다. 연결을 확인하고 다시 시도해 주세요" + 다시 시도(`refetch`)를 보여 준다. 공통 타임아웃은 아직 없다 (확인 필요 — `useAPI`에 시간 제한 옵션이 없다).
- 10초 이상 작업은 시작할 때 예상 시간을 문구로 알린다 ("약 1분 걸립니다").
- 취소한 뒤에는 이전 화면 상태로 돌아가고, 일부만 처리됐으면 무엇이 처리됐는지 알린다.

## 6. 확인 목록

- [ ] 첫 조회는 스켈레톤, 다시 조회는 기존 화면 유지
- [ ] 1초 미만 작업에 스켈레톤 · 전체 화면 오버레이를 쓰지 않았다
- [ ] 저장 버튼은 요청 중 비활성 (`isPending`)
- [ ] 3초 이상 작업에 진행률 또는 단계 문구가 있다
- [ ] 10초 이상 작업에 취소가 있다
- [ ] 로딩 영역에 `role="status"` 문구, 움직임 줄이기 설정에서도 진행 중임이 보인다
- [ ] 시간이 지나면 멈추고 에러 + 다시 시도로 바뀐다
